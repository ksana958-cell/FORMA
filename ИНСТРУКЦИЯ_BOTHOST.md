# Пошаговая установка FORMA на BotHost

*Для Windows, GitHub и существующего аккаунта BotHost. Cloudflare не нужен.*

## Шаг 0 — скачайте и распакуйте архив

Распакуйте ZIP. В корне должны сразу лежать `app.js`, `Dockerfile`, `package.json`, `schema.sql` и папка `public`.

**Не загружайте в репозиторий папку поверх папки:** файл `app.js` должен оказаться в корне GitHub-репозитория, а не внутри `FORMA_2_1_BOTHOST/app.js`.

## Шаг 1 — создайте Telegram-бота

1. Откройте https://t.me/BotFather.
2. Отправьте `/newbot`.
3. Выберите видимое имя, например `FORMA Fitness`.
4. Выберите свободный username, заканчивающийся на `bot`, например `forma_gleb_fit_bot` (пример — может быть занят).
5. BotFather выдаст **токен**. Сохраните его в менеджере паролей. **Не публикуйте в GitHub и не присылайте мне в чат.**

## Шаг 2 — загрузите проект в GitHub

1. На https://github.com/new создайте репозиторий `forma-telegram-app`. Для личного дневника предпочтительнее `Private`, если ваш тариф и настройки BotHost допускают подключение приватного репозитория; иначе убедитесь, что никакие секреты не добавлены в Git.
2. Создайте пустой репозиторий, не добавляя шаблонных файлов.
3. Нажмите **uploading an existing file** / **Add file → Upload files** и загрузите **содержимое распакованной папки**. Важно сохранить структуру папок `public/`, `src/` и `scripts/`.
4. Нажмите **Commit changes**. Убедитесь, что `app.js`, `Dockerfile` и `package.json` видны в корне репозитория.
5. Скопируйте адрес GitHub-репозитория.

Если GitHub в браузере неудобно загружает вложенные папки, можно перетащить всю структуру из проводника Windows в окно загрузки или воспользоваться GitHub Desktop.

## Шаг 3 — создайте приложение в BotHost

1. Перейдите в https://bothost.ru/dashboard.php и выберите создание нового бота.
2. Платформа — **Telegram**, язык — **Node.js** (или пункт **Dockerfile**, если он есть отдельно в текущем интерфейсе).
3. Вставьте токен BotFather в поле токена бота.
4. Вставьте Git URL репозитория, ветка `main`.
5. В дополнительных настройках включите **использование собственного Dockerfile** (файл уже есть в корне проекта). Он устанавливает Node.js 24 и использует надёжный каталог `/app/data` для SQLite и снимков формы.
6. Включите **Использовать домен / веб-приложение**, задайте порт **3000**, если интерфейс просит выбрать вручную. Код читает `PORT` автоматически и слушает `0.0.0.0`.
7. Сохраните настройки и запустите сборку/деплой. В логах ищите `Listening on 0.0.0.0:3000` (цифра порта может отличаться).

Если BotHost выдаёт ошибку Dockerfile или недоступен тарифный HTTPS-домен, проверяйте журнал сборки и доступность опции у вашего тарифа до дальнейших шагов.

## Шаг 4 — включите HTTPS-домен

После публикации BotHost покажет HTTPS-адрес, например `https://имя-проекта.bothost.tech` или в зоне `.bothost.ru` (пример, не готовый адрес).

Откройте его в браузере: должна загрузиться FORMA. В обычном браузере включается локальный деморежим — это нормально. Для сохранения в облачную базу откройте приложение из Telegram.

В отдельной вкладке проверьте `https://ВАШ-ДОМЕН/api/health`. В ответе должны быть `"ok":true` и `"databaseConfigured":true`.

## Шаг 5 — добавьте секреты в BotHost

В панели вашего приложения найдите раздел **Переменные окружения / Environment Variables**. Добавьте:

| Название | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен от BotFather (если BotHost ещё не предоставляет его под этим именем) |
| `WEBHOOK_SECRET` | Произвольная случайная строка 32–64 символа из латинских букв и цифр |
| `PUBLIC_BASE_URL` | Точный HTTPS-адрес приложения из BotHost **без `/` в конце** |

Случайный секрет можно создать у себя на компьютере через Node.js:

```bash
node -e "console.log(require('crypto').randomBytes(24).toString('hex'))"
```

Для работы уведомлений **не нужен отдельный cron или процесс** — проверка расписания встроена в Node-сервер и выполняется раз в минуту, пока контейнер работает.

После сохранения переменных выполните **перезапуск приложения** (если настройки BotHost требуют — повторный деплой). В логах должно появиться `Telegram webhook and menu button configured`.

## Шаг 6 — узнайте свой Telegram ID и ограничьте доступ

1. Откройте чат со своим новым ботом в Telegram.
2. Отправьте `/start`.
3. Если `OWNER_TELEGRAM_ID` пока не указан, бот ответит твоим числовым Telegram ID и подскажет, что делать.
4. Добавьте в переменные BotHost `OWNER_TELEGRAM_ID=...` — именно **числовой ID**, не @username.
5. Сохраните переменную и перезапустите контейнер.
6. Ещё раз отправьте `/start`. Бот должен предложить кнопку **Открыть FORMA**; также появится кнопка меню в его чате.

Без этого ID сервер намеренно не даёт доступ к личному дневнику. Даже при знании URL другие пользователи не смогут просматривать твои данные через API.

## Шаг 7 — начните пользоваться

- Открой FORMA **в Telegram** через кнопку меню или из ответа `/start`.
- В разделе тренировок запусти программу Пн/Ср/Пт, отметь подход, закончи занятие; проверь календарь.
- В разделе питания добавь блюдо вручную или из недельного меню.
- Открой «Прогресс», запиши вес и талию, проверь загрузку фото.
- В настройках укажи локальное время напоминания и включи уведомления.
- Закрой мини-приложение и открой его в Telegram на другом устройстве — данные должны подгрузиться из SQLite.

## Шаг 8 — дополнительные функции (необязательно)

**ИИ-фотоанализ:** создай отдельный API-ключ в https://platform.openai.com/, настрой оплату API и добавь переменную `OPENAI_API_KEY` в BotHost. Подписка на ChatGPT не заменяет API-биллинг. Модель по умолчанию: `gpt-4.1-mini`. Не отправляй ключ в чат и GitHub. Оценки еды по фото приблизительные, перед сохранением проверь порцию.

**Поиск по штрихкоду:** добавь `OFF_CONTACT=адрес_почты_для_запросов`. Эта почта используется как контакт приложения при запросах Open Food Facts.

**Ручная переустановка Telegram webhook:** при необходимости открой терминал BotHost и запусти `node scripts/setup-telegram.mjs` из каталога приложения (`/opt/forma` при Dockerfile из архива). Обычно это не требуется — настройка автоматическая.

## Шаг 9 — сохранность данных и обновления

- Обновляй код коммитом в GitHub и используй функцию обновления/деплоя в BotHost. Структура базы автоматически инициализируется через `CREATE TABLE IF NOT EXISTS`.
- Сама база хранится в `/app/data/forma.sqlite`, фотографии — в `/app/data/private-photos`. **Папку `/app/data` нельзя стирать при обновлениях.**
- Для резервной копии запусти `node scripts/backup.mjs` через терминал приложения. Копия появится в `/app/data/backups/дата-время`. Скачай её через файловый менеджер BotHost и храни приватно.
- Для личного проекта нет необходимости создавать Cloudflare D1, R2 или Workers.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Сайт выдаёт 502/504 | Порт в BotHost совпадает с `PORT`; приложение слушает `0.0.0.0`, проверь логи. |
| `/start` молчит | Указаны BOT_TOKEN, WEBHOOK_SECRET, PUBLIC_BASE_URL; последняя запись в логах об успешном webhook; HTTPS включён. |
| «Открой приложение внутри Telegram» | Ты открыл сайт обычным браузером, а не кнопкой из чата Telegram. |
| «Приложение доступно только владельцу» | Неверный `OWNER_TELEGRAM_ID`. |
| Дневник не сохраняется | Путь `/app/data` доступен на запись, `api/health` говорит databaseConfigured=true. |
| Напоминания не приходят | `/start` от владельца уже был, напоминания включены в настройках, выбран часовой пояс, BotHost не усыпляет контейнер. |
| Фото еды не распознаётся | Нужен отдельный оплачиваемый OpenAI API-ключ; без него пользуйся ручным вводом. |
| После обновления пропали данные | Проверь, что каталог `/app/data` не очищался; восстанови из резервной копии. |

Официальная документация BotHost: https://bothost.ru/docs/manual-mini-app, https://bothost.ru/docs/domains-and-ports и https://bothost.ru/docs/database-storage.
