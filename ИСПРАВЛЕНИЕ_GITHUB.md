# Исправление Bad Gateway / ERR_MODULE_NOT_FOUND

В репозитории файлы были загружены без папок. Node.js выполняет `app.js`, который импортирует `./src/worker.js`, но `worker.js` находится в корне GitHub. **В ZIP структура правильная**.

## Сделать сейчас (без создания нового бота)
1. Распакуйте ZIP на ПК: должны быть папки `src`, `public`, `scripts` рядом с `app.js` и `Dockerfile`.
2. Откройте свой репозиторий GitHub `ksana958-cell/FORMA`, ветку `main`.
3. Нажмите **Add file → Upload files**.
4. В Windows Проводнике выделите **именно папки** `src`, `public`, `scripts` и **перетащите их в окно загрузки GitHub**, НЕ файлы внутри них. Если GitHub отобразит имена без `src/`, `public/`, `scripts/`, отмените загрузку.
5. Дополнительно можно перетащить из распакованного архива файл `Dockerfile`: в новой версии он проверяет наличие папок прямо во время сборки.
6. Нажмите **Commit changes**. Проверьте, что на GitHub появились ссылки `src/worker.js`, `public/index.html`, `public/app.js`, `scripts/setup-telegram.mjs`.
7. BotHost → FORMA → обновить / пересобрать из GitHub. Нужна **новая сборка**, просто Restart старого контейнера не подтянет файлы.
8. После пересборки откройте свой адрес `/api/health`. Если вернётся `ok: true`, отправьте Telegram-боту `/start`.

## Важно
- В опубликованном скриншоте виден `WEBHOOK_SECRET`. Замените его новым случайным секретом в настройках BotHost и перезапустите бота после исправления структуры. Бот сам перепривяжет webhook при старте.
- Не публикуйте `BOT_TOKEN`, `WEBHOOK_SECRET`, `OPENAI_API_KEY` в GitHub или скриншотах.
- Не удаляйте `/app/data`: там история тренировок и фотографии.
- Старые файлы, ошибочно лежащие в корне GitHub, можно удалить позднее. Сначала убедитесь, что сайт и бот запускаются.
